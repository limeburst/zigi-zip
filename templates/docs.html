zigi.zip · API

signed in as {{ signed_in }}

Upload files from scripts. Each upload gets a short link, as uploads here do, that stops working after {{ default_days }} day, or when you say. Short codes are easy to type, and as easy to guess: don't upload anything through a link you couldn't stand a stranger finding before it expires.

Sign in

Send your upload password in the Authorization header, the same password you sign in with here:

Authorization: Bearer <password>

An API request leaves no session behind. Revoking or rotating the password stops scripts that use it.

Upload a file

Send the file as the body of a PUT, named in the URL:

curl -H "Authorization: Bearer $ZIGI_PASSWORD" \
     -T app.zip {{ base_url }}/api/files/app.zip

or as the file field of a multipart POST, as a browser form would:

curl -H "Authorization: Bearer $ZIGI_PASSWORD" \
     -F file=@app.zip {{ base_url }}/api/files

From PowerShell, where there is no curl:

Invoke-RestMethod -Method Put -InFile app.zip `
  -Headers @{ Authorization = "Bearer $env:ZIGI_PASSWORD" } `
  -Uri {{ base_url }}/api/files/app.zip

How long the link lasts

{{ default_days }} day unless you add ?expires=: a number with m, h or d, from 1 minute to {{ max_days }} days.

curl -H "Authorization: Bearer $ZIGI_PASSWORD" \
     -T app.zip "{{ base_url }}/api/files/app.zip?expires=2h"

After that, the link answers 404, and the file is deleted within a few minutes (unless another link has the same file). Change it later under my stuff, for any file of yours, uploaded here or through the API: in an hour, a day, 7 or 30 days, or never.

The answer

The link, on a line of its own (status 201):

{{ base_url }}/Xk7

With Accept: application/json, the details too:

{
  "url": "{{ base_url }}/Xk7",
  "code": "Xk7",
  "name": "app.zip",
  "size": 1048576,
  "sha256": "9f86d08…",
  "expires_at": "2026-11-19T13:00:00+00:00"
}

A browser shows what it can (images, PDFs, text) and saves the rest. Add ?download to the link to have it always saved: {{ base_url }}/Xk7?download. curl and PowerShell always save it.

Check what you download against sha256:

curl -fsSLo app.zip {{ base_url }}/Xk7
shasum -a 256 app.zip                     # macOS, Linux
Get-FileHash app.zip -Algorithm SHA256    # PowerShell

Errors

401no password, or a wrong one
400no file, a bad name, or a bad expires
502storage did not take the file; try again

The body says what went wrong: error: …, or {"error": "…"} with JSON.
